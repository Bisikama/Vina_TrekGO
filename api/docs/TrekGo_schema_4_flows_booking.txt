TREKGO — SCHEMA HIỆN TẠI CHO 4 FLOW TRIP VÀ BOOKING
Nguồn: api/prisma/schema.prisma
Ngày xuất: 2026-09-24

PHẠM VI
F1. Leader tạo Public Trip: User/LeaderProfile → Trip DRAFT → checkpoint + System Trail plan → OPEN.
F2. User tạo Private Trip: User → PersonalTrail của mình hoặc TrailAccess ACTIVE → Trip → TripMember HOST → Invite.
F3. User mua chỗ Public Trip: Trip OPEN → Booking PENDING_PAYMENT + Participant → Invoice/Payment → CONFIRMED.
F4. User tham gia Private Trip bằng mã: PrivateTripInvite → kiểm tra hạn/lượt/capacity → TripMember ACTIVE.
Các mũi tên mô tả nghiệp vụ; không phải mọi bước đã được schema hoặc service cưỡng chế.

CÁCH ĐỌC
- Mỗi field hiển thị: tên cột DB | nguyên khai báo field Prisma (kiểu, NULL, default, thuộc tính).
- Dấu ? = nullable. @id = khóa chính. @unique/@@unique = duy nhất. @@index = index thường.
- @map đổi tên field sang cột DB; @@map là tên bảng DB.
- String @db.Uuid = UUID; Int = integer; Boolean = boolean; Json = jsonb.
- String không có @db.* mặc định là text với PostgreSQL.
- DateTime @db.Timestamptz(6) = thời gian có múi giờ; @db.Date = ngày.
- @default(uuid()) được Prisma sinh; không mặc nhiên là DEFAULT UUID trong PostgreSQL.
- @updatedAt do Prisma xử lý, không phải database trigger.
- Quan hệ FK được giữ nguyên khai báo Prisma ở mục riêng.
- Không liệt kê inverse relation fields (mảng/quan hệ ngược) vì chúng không phải cột DB.
- Đây là bản tra cứu, không phải file schema.prisma độc lập có thể chạy migration.
- Bảng dùng chung có thể còn FK tới domain ngoài phạm vi; vẫn giữ đủ cột hiện hữu.
- Không bao gồm GPS runtime, kho/rental, xét duyệt Leader chi tiết, review hoặc gamification.

LƯU Ý NGẮN VỀ SCHEMA HIỆN TẠI
1. TripTrailPlan bắt buộc systemTrailId: flow Private dùng PersonalTrail chưa có liên kết plan tương ứng.
2. Trip chưa có pickupPointId và chưa có TripPickupPoint; điểm đón hiện nằm ở Booking/Member/Transport.
3. LeaderProfile vẫn có LeaderType EXPERT/COMMUNITY; tài liệu v2 dùng một role LEADER, không phân tier cho MVP.
4. Chưa có BookingIdempotencyRequest hoặc BookingInboxEvent; confirmationIdempotencyKey không thay cho key tạo hold.
5. Comment nhắc CHECK/partial unique/EXCLUDE nhưng không xem đó là constraint đã triển khai. Cần kiểm tra migration/DB thực tế.
6. UNIQUE(tripId,userId) ở TripMember áp dụng cả bản ghi LEFT/REMOVED: tham gia lại cần xử lý bản ghi hiện có.
7. PersonalTrailVisibility có SHARED trong schema; không mặc nhiên cho phép public Personal Trail theo tài liệu.
